# 星脈遠征：手機式地圖挖寶與前端技術規格

> 版本：v0.6.0（可玩技術切片）
> 範圍：單機 GitHub Pages 原型；第一張「星砂群島」8×8 地圖。

## 1. 結論：先做畫面層，再擴內容

挖寶的感覺不靠堆更多地圖圖片，而靠三件事同時成立：

1. **規則穩定**：寶物、地形、已翻格與專注可保存、可重播、可測試。
2. **畫面可信**：每一次挖掘都有翻開地表、粒子、文字與已發現物，資料不會無預警跳變。
3. **操作像手機遊戲**：手指在地圖內拖曳時移動鏡頭，輕點時挖掘；離開地圖後，網頁仍可自然捲動與縮放。

v0.6.0 因此先交付一張完整可玩的原創地圖與可重用 Canvas 畫面層。它不是通用大型遊戲引擎，也不需要完整剛體物理；本玩法真正需要的是**鏡頭慣性、點擊命中、視覺粒子與固定節奏更新**。

## 2. 研究依據

| 問題 | 研究結論 | 本作決定 |
|---|---|---|
| 高解析手機螢幕會讓 Canvas 變糊 | [`devicePixelRatio`](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio) 可用 CSS 像素與實體像素的比例重建繪圖緩衝區。 | Canvas 依容器尺寸重建，DPR 上限設為 2；瀏覽器縮放與旋轉只重繪，不改變邏輯格子或存檔。 |
| 觸控、滑鼠、觸控筆需要一套輸入 | [Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events) 以同一事件模型處理各種指標，並可用 pointer capture 維持拖曳。 | 僅 Canvas 監聽 pointer 事件；8px 內視為點擊、超過則為鏡頭拖曳。 |
| 地圖拖曳不能帶動整個頁面，但使用者仍要能縮放閱讀 | CSS [`touch-action`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action) 用來宣告觸控手勢交給瀏覽器或元素處理。 | 只對 `#expedition-canvas` 設 `touch-action: none`；沒有鎖住 `body`，沒有 `user-scalable=no`，地圖外仍保留捲動與瀏覽器縮放。 |
| 每台螢幕更新頻率不同 | [`requestAnimationFrame`](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame) 配合顯示器更新；動畫程式不能假設固定幀率。 | render 使用 rAF；simulation 用 1/60 秒固定步長與 100ms 上限，避免切換分頁後鏡頭或粒子瞬移。 |
| 玩家懷念的挖寶不是盲點 | [既有 Treasure Isle 歷史研究](10_TREASURE_ISLE_RESEARCH_AND_EXPANSION.md) 顯示逐格未知、遠近線索、能量路線、套組收藏與成果展示才是可轉譯的核心。 | 使用原創星脈羅盤、星砂地形與回聲博物間，不使用原作名稱、版面、寶物或介面。 |

## 3. v0.6.0 的技術切片

```text
expedition-engine.js              純規則：種子、地形、相鄰可達性、專注、羅盤、發現物
          ↓ immutable result
town.js                           共用存檔：資源、收藏、遠征地圖快照、schema 遷移
          ↓ serializable state
expedition.js                     DOM HUD、按鈕與可讀文字，呼叫存檔／通知
          ↓ state + event
expedition-renderer.js            Canvas：DPR、鏡頭、慣性、命中、地格、粒子
```

- 規則層不讀 Canvas、DOM 或時間；相同 seed 會產生相同地形與寶物位置。
- 畫面層不能決定獎勵、寶物位置或探索合法性；它只顯示引擎回傳的事件。
- `starcare-hollow:town:v1` 維持不變，內容 schema 升至 v5。舊 v1～v4 存檔會補一張新地圖，而不覆寫既有資源與收藏。
- 每次成功挖掘先在畫布上產生翻土／星光粒子與文字紀錄，再由 HUD 顯示新的專注和羅盤；這延續「結果必須先被看見」原則。

## 4. 遊戲規則：星砂群島

| 項目 | v0.6.0 實作 |
|---|---|
| 地圖 | 8×8；起點 `(1,1)` 已開啟，只可開啟其上下左右相鄰格。 |
| 地形 | 星砂 1、月藤 2、晶岩 3 專注；地形和寶物均由固定 seed 保存。 |
| 主要寶物 | 3 件：潮音貝譜、雲航刻尺、古療瓶；找一次即永久保留。 |
| 線索 | 以未取得主要寶物的切比雪夫距離顯示：近旁、強烈、微弱、寂靜；並附完整文字。 |
| 結果 | 發現寶物才發星幣／星砂；已翻格、專注、發現物與地圖完成狀態自動保存。 |
| 失敗處理 | 專注不足只停止本次調查，沒有倒扣、倒數、清空或錯過內容。 |

## 5. 畫面與「物理」邊界

### 5.1 需要的動態，不做假的重量感

- **鏡頭**：拖曳直接帶動世界座標；放手後以阻尼衰減慣性，並限制在地圖範圍外約 0.35 格內。
- **挖掘**：不是硬體物理。合法點擊會把資料格從迷霧改為地形，並從該格發射有限數量的粒子。
- **粒子池**：最多 40 顆；發現主要寶物 26 顆、普通挖掘 12 顆；`prefers-reduced-motion` 時最多 8 顆。
- **層次**：雲海背景 → 地圖格 → 地形細節／寶物 → 鍵盤選格與拖曳高亮 → 粒子。這樣可以在中階手機維持清楚且不依賴大量圖片。

不引入 Box2D、Pixi 或大型遊戲引擎。它們會增加首屏與升級成本，卻不會改善這個逐格推理玩法；若未來需要角色走路、碰撞、多地圖同屏或 100+ 動態物件，再評估升級到資料驅動 sprite layer 或專用引擎。

### 5.2 縮放與輸入不可破壞規則

1. CSS 尺寸、Canvas 內部像素尺寸、邏輯格座標完全分開。
2. `ResizeObserver` 或 DPR 改變只會呼叫 renderer resize；不能重新建種子、重置鏡頭進度、重發獎勵。
3. `preventDefault()` 僅存在 Canvas 的 pointer 事件內；沒有 document/body 層級的觸控攔截。
4. Canvas 可聚焦：方向鍵選格、Enter／Space 調查；同時提供 44×44 CSS px 的方向按鈕與「調查」按鈕。
5. 不能只用顏色表示羅盤：Canvas、標題、說明文字與即時紀錄都要一致。

## 6. 可擴充路線

| 下一步 | 只新增資料 | 需要新增規則 |
|---|---|---|
| 第二、三張星砂地圖 | 地圖定義、seed、寶物池、地形分布 | 無 |
| 工具：月芽剪、共鳴鎬、回聲鏡 | 工具文案、圖示、耐久 | 成本修正、鄰格輪廓、方向比較事件 |
| 套組與博物間 | 套組定義、展示物、完成獎 | 保底與重複轉換 |
| 同行者技能 | 角色能力資料 | 可讀取引擎事件，不可直接改 Canvas |
| 多地圖選擇 | `expeditions.json` | 地圖切換、進度索引、解鎖條件 |

正式內容會將目前程式內的第一張地圖搬到 JSON；在可玩範圍尚小時，先保留程式內 seed 可避免多一個未驗證的載入管線。

## 7. 驗收清單

- 同 seed 的地形和主要寶物位置一致；重新載入後已翻格、專注和收藏一致。
- 非相鄰格、已翻格、專注不足格都不能扣除專注。
- 成功挖掘必有可見的地格改變、即時文字和粒子；發現寶物還要寫入手札。
- 390×844、桌面、200% 瀏覽器縮放下沒有水平溢位，Canvas 清楚且不重置進度。
- 地圖內可拖曳不拖動頁面；地圖外單指滑動仍可捲頁；頁面未禁止使用者縮放。
- 鍵盤與降低動態可完整完成一格調查。
- `npm run check` 覆蓋 seed、合法性、發現、遷移、畫布契約與既有小鎮規則。
