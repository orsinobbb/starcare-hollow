# UX、介面、操控與無障礙規格

版本：v0.4。核心操作是「選居民、判讀需求、點相符站點、施放搭檔技能」；不使用串珠、消除或拖曳連線。

## 1. 資訊架構

主導覽固定為五個目的地：

1. 小鎮：建設、日常目標、居民狀態與入口。
2. 療癒所：即時服務班次。
3. 收藏冊：居民、故事、服裝、家具、配方、地標與紀念物。
4. 星願手札：主線、分岔、已讀節點與回溯。
5. 設定：聲音、顯示、操控、難度與存檔。

任何核心功能從小鎮最多三次操作抵達。返回鍵先關閉最上層面板，再回到小鎮；不可因返回而遺失班次結果。

## 2. 核心流程

### 2.1 開始班次

小鎮療癒所 → 班次簡報 → 選擇難度與搭檔 → 開始 → 即時派遣 → 結算 → 獎勵與收藏提示 → 返回小鎮。

簡報只顯示：主要居民、可能需求、特殊規則、目標、可帶入搭檔。第一次遇到的新規則以一張示意卡解釋。

### 2.2 小鎮建造

小鎮 → 選建築或空地 → 預覽需求與完成變化 → 確認建造 → 短演出 → 解鎖內容。

家具佈置使用獨立模式；進入後才允許拖曳，並明確顯示「完成」與「復原」。班次頁不使用拖曳，避免手機滑頁衝突。

```text
├──────────────┬─────────────────────┬───────────────────────┤
│ 居民佇列     │ 目前居民            │ 四座照護站            │

```

窄螢幕依序堆疊：目前居民 → 居民佇列 → 站點 → 技能 → 統計。所有核心內容隨頁面正常垂直捲動；點擊或按住按鈕不得帶動整頁橫向位移。

### 視覺優先順序

1. 目前居民的肖像、需求與耐心。
2. 相符站點與站點冷卻。
3. 急迫居民。
4. 可施放的搭檔技能。
5. 班次目標、流暢度與分數。
6. 裝飾與環境動態。

## 4. 核心互動

### 4.1 選擇居民

- 點擊居民卡即選中；選中框、放大肖像與文字提示同時更新。
- 現在選中的居民必須有 `aria-pressed="true"` 或等價狀態。
- 急迫不只用紅色：同時使用粗外圈、驚嘆圖形與「急迫」文字。
- 已完成居民播放短慶祝後退出，不留不可操作殘影。
- 若未手動選擇，系統預選耐心最低且仍有需求的居民。

### 4.2 派遣站點

- 四個固定站點：觀察、調製、療護、安撫。
- 每個站點同時使用獨特圖形、名稱、動詞與色彩。
- 點相符站點會扣除工作量、啟動短冷卻、增加技能充能並更新流暢度。
- 點錯站點不扣資源；只給柔和回饋並將相符站點短暫描邊。
- 冷卻按鈕顯示剩餘時間與進度環，不能靠降低透明度作為唯一提示。
- 玩家操作後立即更新畫面；視覺不得出現「數值已結算但畫面仍停留」的假象。

### 4.3 搭檔技能

- 四次正確派遣充滿共用技能條；平衡值可由資料表調整。
- 滿格後三張技能均可選，施放一張即消耗整條充能。
- 月芽綻放：完成最多兩位最急迫居民的當前需求。
- 星時停駐：暫停耐心八秒並重置所有站點冷卻。
- 安心抱抱：全體恢復 35％耐心，療癒所穩定度增加 10。
- 技能卡以角色肖像為主、效果圖形為輔；可用狀態有金邊、呼吸亮度與文字三重提示。
- 效果演出可跳過，且不得阻擋下一次派遣超過 300 ms。

### 4.4 流暢度

- 在五秒內連續正確派遣會提升流暢度；不是連珠或消除。
- 流暢度中斷只回到基本倍率，不倒扣已得分數。
- 回饋以短文字、微光與音階呈現，不做全畫面震動。

## 5. 輸入配置

| 動作 | 鍵鼠 | 觸控 | 鍵盤 |
|---|---|---|---|
| 選居民 | 左鍵 | 單點 | Tab 後 Enter／Space |
| 派站點 | 左鍵 | 單點 | 1～4 或焦點後 Enter |
| 技能 | 左鍵 | 單點 | Q／W／E 或焦點後 Enter |
| 暫停 | Esc／按鈕 | 按鈕 | Esc |
| 說明 | 按鈕 | 按鈕 | H |
| 頁面捲動 | 滾輪／捲軸 | 單指垂直滑動 | PageUp／PageDown |

規則：

- 核心玩法只需單點，不要求長按、快速連點、多指或精密拖曳。
- 觸控核心目標至少 44×44 CSS px，建議 56 px。
- 互動元件使用原生 `button` 或等價語意，不以 `div` 偽裝。
- `touch-action` 只限制按鈕本身，不鎖死整頁正常垂直捲動。
- 滑動頁面不會誤觸站點；站點按下後也不會拖動畫面。

## 6. 畫面清晰度

### 6.1 四類需求

| 類型 | 圖形 | 主色 | 文字動詞 |
|---|---|---|---|
| 觀察 | 眼形 | 靛藍 | 觀察 |
| 調製 | 葉形 | 翠綠 | 調製 |
| 療護 | 四瓣十字 | 珊瑚紅 | 療護 |
| 安撫 | 心形 | 金黃 | 安撫 |

色彩不是唯一線索。圖形輪廓需在 32 px 可辨，文字與背景對比至少 4.5:1，大型圖示至少 3:1。

### 6.2 角色可愛度

- 居民卡至少保留眼睛、嘴型與一個代表配件，縮圖仍看得出個性。
- 同畫面居民在髮型、輪廓、年齡、體型或物種至少有兩項差異。
- 急迫表情表達需要協助，不以痛苦或恐怖表演刺激玩家。
- 技能演出強化角色魅力，絕不能把角色縮成單純數值按鈕。

### 6.3 舒適觀察

找線索與找不同只作為可選支線：

- 單張圖最多 5 個目標。
- 不依賴低對比、極小差異或快速閃現。
- 每 90 秒可使用一次不扣分提示。
- 可縮放 200％，命中區至少 44×44 CSS px。
- 不用時間壓力迫使玩家長時間盯著細節。

## 7. 教學設計

### 原則

- 先做一次，再給名稱；每次只教一個新概念。
- 教學聚光只鎖定當下必要按鈕，其他頁面仍可暫停或離開。
- 同一提示失敗兩次後改用動畫示範；三次後提供自動完成。
- 已學內容可在說明頁用 20 秒內重看。

### 前 20 分鐘

| 時間 | 新內容 | 成功訊號 |
|---:|---|---|
| 0～3 分 | 選居民、點相符站點 | 完成第一位居民 |
| 3～7 分 | 多步需求、站點冷卻 | 完成四次正確派遣 |
| 7～10 分 | 充能與安心抱抱 | 主動施放一次技能 |
| 10～14 分 | 急迫排序與流暢度 | 救回一位急迫居民 |
| 14～17 分 | 班次結算與收藏 | 解鎖第一件非資源收藏 |
| 17～20 分 | 小鎮建設與分岔預覽 | 完成一個短期修復目標 |

## 8. 結算畫面

先呈現結果，再說明原因：

- 星級、服務人數、最高流暢度、使用技能次數。
- 新紀錄與首次收藏獨立翻牌。
- 療癒幣、材料與收藏分開列，不把收藏藏進資源數量。
- 未達目標時說明最主要的一個原因，並提供「再試一次」與「舒適模式」。
- 返回小鎮後，相關建築、居民或收藏立即出現可見變化。

## 9. 無障礙

### 視覺

- 介面縮放 80～160％；瀏覽器 200％縮放仍可操作。
- 高對比模式、色覺友善圖形、降低粒子、降低動態。
- 不用全畫面閃白；高對比閃爍不超過每秒三次。
- 所有肖像與功能圖示有替代文字。

### 動作與認知

- 舒適模式把耐心下降速率調為標準的 70％，不減故事或收藏獎勵。
- 可暫停、可跳過技能演出、可關閉畫面震動。
- 允許固定選中居民，不因週期重繪奪走焦點。
- 數字倒數同時提供進度條或環形提示。
- 重要規則使用一致詞彙，不在「照護／治療／服務」間隨意更換按鈕名稱。

### 聽覺

- 音樂、環境、介面、角色四路音量。
- 所有必要音訊有視覺對應；字幕可調大小與背景。
- 流暢度音階可改為低音量節奏敲擊。

## 10. 通知、時間與存檔

- 生產完成通知可依類型關閉；每日最多三則裝置通知。
- 離線進度回來一次結算，不連續彈窗。
- 班次結束、建造完成、劇情選擇前後自動存檔。
- 遊戲中斷重新載入時回到安全節點；不重複發一次性獎勵。
- 存檔版本升級須保留小鎮、收藏、歷史分數與技能使用紀錄。

## 11. 錯誤與復原

- 點錯站點不扣材料，也不清除已累積充能。
- 網路中斷不影響本地單機班次；同步恢復後再合併結果。
- 存檔讀取失敗時保留上一個輪替備份並顯示可理解訊息。
- 版本不相容不靜默重置；先備份，再遷移，再驗證。
- 所有破壞性動作需二次確認，並說明可否復原。

## 12. UX 驗收清單

- 初次玩家 60 秒內能在無口頭指導下完成第一位居民。
- 玩家能說出四種需求與相符站點，不會誤以為是消除遊戲。
- 完成四次正確派遣後，玩家知道技能已可施放。
- 桌機與 360 px 寬手機皆不出現水平溢位。
- 手機垂直滑頁正常，單點站點不帶動畫面。
- 週期更新不會讓按鈕失焦、漏點或出現畫面未同步。
- 灰階、低動態、200％縮放與鍵盤操作均可完成一班。
- 結算後，小鎮與收藏冊的進度立即一致。
